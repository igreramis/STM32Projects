## Reproduced defect and change

`wait_for_rom()` accepted any `0x79` byte as an acknowledgement. The running
application's state JSON contains ASCII `y` in `"type"` and sometimes `"ready"`.
Tests showed identification could begin on these bytes without any ROM response.

The receiver now ignores an observed JSON line from `{` through newline, across
reads/probes, before accepting a standalone ACK. NACK still stops immediately;
noise, attempts and total time remain bounded. An interrupted JSON line is treated
conservatively; an ambiguous ACK inside it is not accepted. This does not guarantee
recognition of arbitrary corrupted/truncated serial input. Full ROM identity,
geometry, predecessor, signing and flash verification checks remain mandatory.

Fixed-vocabulary local logs record acknowledged sync, the identification command
being started, and validated identity. Raw UART data and exception text are not
logged, and cloud error messages are unchanged. No automatic reset or retry was added.
